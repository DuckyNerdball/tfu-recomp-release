## How to play
You need your own **two Xbox 360 disc images (.iso)** of Star Wars: The Force Unleashed - Ultimate Sith Edition.
1. In [RecompLauncher](https://recomplauncher.com), install this game and give it Disc 1 and Disc 2.
2. Tick **Build tools** on the setup screen. If Git, Visual Studio 2022 Build Tools or LLVM/clang are missing, setup
   installs them (about 10 GB) and Windows asks for administrator approval once.
3. Wait for the build (one to two hours the first time, about 50 GB free), then press Play.

Nothing is downloaded from the game: it is built on your PC from your discs. Without the launcher, see Quick start.

Native Windows build of **Star Wars: The Force Unleashed - Ultimate Sith Edition** (Xbox 360), made by static
recompilation with the ReXGlue SDK. Unofficial fan project, not affiliated with or endorsed by Lucasfilm, Disney or
Microsoft. This repo holds only original code, build scripts, notes,
and function names/addresses. **It contains no game files, and none may ever be added.** You need your own two
discs.

## What works
- Boots and plays: main story plus the Jedi Temple, Tatooine and Hoth campaigns, all in the New Game picker.
- Saving and loading, with an automatic save backup on every launch (newest 10 kept in `saves\`).
- Sharper picture: resolution scale, sharpening, 16x filtering, optional "clean" look (less blur, bloom and haze).
- In-game menu (F9, or L3+R3 on a pad) with tabs: Player, Powers, Characters, Unlock, World, Console.
  - Cheats that stay on across deaths and relaunches (god mode, infinite Force, game speed, body size).
  - Play as any of the 69 characters, swapped live in place.
  - Enemy spawn multiplier, enemy type mixing, puppet mode (drive an enemy with the pad).
  - Lua console running in the game's own script engine.
- Crash reporter with a readable stack in `logs\crash_*.txt`.

Game logic still runs at 30 fps.

## Requirements
- Windows 10/11 x64, a CPU with AVX2 (the build targets x86-64-v3).
- Visual Studio 2022 Build Tools (C++ workload, which includes CMake and Ninja) and clang 20+. The RecompLauncher
  setup installs these when they are missing; `Play.ps1` expects them to be there already.
- ReXGlue SDK with this project's patch (`sdk\`). A stock SDK will not build or run this; `Play.ps1` and
  `tools\Get-Sdk.ps1` fetch, patch and build the right one for you. git is needed for that.
- Your own disc images: put both ISOs in the folder that contains this repo.

## Quick start
```powershell
.\Play.ps1                       # ISOs in the folder that contains this repo
.\Play.ps1 -Games D:\Isos        # ISOs somewhere else
.\Play.ps1 -Scale 3 -Look clean  # extra options go to the game launcher (see Play below)
```
`Play.ps1` takes your game files, builds the repo around them if it is not built yet, and starts the game.
`-Rebuild` rebuilds first (use it after pulling new code); `-BuildOnly` builds without starting. If no built
ReXGlue SDK is found on the PC, it downloads the public SDK, applies `sdk\rexglue-tfu.patch` and builds it into
`.deps\rexglue-sdk` (one time, 30-60 minutes). `-Sdk <path>` or the `TFU_REXGLUE_SDK` variable points at an existing one.

## Build
```powershell
# from the folder that contains tfu-recomp\ and the two ISOs
& .\tfu-recomp\tools\Setup-TFURecomp.ps1 -Root (Get-Location).Path -NoLaunch
```
The script is re-runnable; each stage skips itself when its output exists: extract discs, merge them into
`game_all\`, generate the recompiled code, build, write `tools\run.ps1`. First build takes about an hour.
`-SkipBuild` stops after code generation. Do not build while the game is running.

## Play
```powershell
& .\tools\run.ps1 -Scale 3 -Look clean
```
| Option | Meaning |
|---|---|
| `-Scale 1..4` | internal resolution multiplier (default 2) |
| `-Look stock\|clean` | original picture, or reduced blur/bloom/haze |
| `-Effect cas\|fsr\|bilinear`, `-Sharp x` | output filter and sharpening |
| `-Campaign all\|story\|dlc` | which campaigns New Game offers (default all); each has its own save profile |
| `-Profile name` | use a separate save profile `run\userdata_<name>` |
| `-Diag`, `-Probe` | extra logging for debugging |
| `-BackupOnly` | back up saves and exit |

`tools\run.ps1` is generated by the setup script. Change the generator, not the generated file.

## Layout
| Path | Contents |
|---|---|
| `app\src\` | our code: menu (`tfu_menu.cpp`), Lua console/cheats/character swap (`tfu_lua.cpp`), crash reporter |
| `app\tfu_manifest.toml` | recompiler input: function-discovery fixes |
| `app\generated\` | recompiled game code, generated locally, never committed |
| `launcher\` | RecompLauncher package (manifest, setup step, Play) |
| `tools\` | setup/build script, function-import helpers, unattended test helper |
| `sdk\` | the SDK patch and the SDK commit it applies to |
| `docs\` | status log, work plan, the game's 1588 script function names and signatures |
| `game_disc1\`, `game_disc2\`, `game_all\`, `dumps\`, `run\`, `logs\`, `saves\` | local only, git-ignored |

## Live debugging
While the game runs, write a Lua chunk to `run\lua_in.txt`; the result appears in `logs\lua_out.txt`.
Call game functions as `F"Name"(...)`; start a chunk with `=` to print a value. See `docs\lua_signatures.txt` for the list of
game functions and their arguments.

## RecompLauncher
`launcher\` holds the RecompLauncher package: `recomplauncher.json`, a windowless setup step (`Prepare.cmd` ->
`Install-TFU.ps1`) and `Play.cmd`. The player gives it Disc 1 and Disc 2; setup downloads this source, builds the
SDK if the PC has none, extracts the discs and builds the game, printing progress for the launcher. Play starts
`tools\run.ps1`, with Resolution and Picture settings shown in the launcher.

```powershell
.\tools\Package-Launcher.ps1 -Dev             # test locally: out\launcher\, then Developer tools > Add a build
.\tools\Package-Launcher.ps1 -Version 0.1.0   # release zip: out\TFU-Recomp-v0.1.0-Windows-x64.zip
```
The setup step does not install Visual Studio, clang or Git; it stops and names what is missing.
